Reading a CI run

You just opened PR #8 and a green tick appeared. This lesson decodes what that tick is — and, more importantly, what it is not — vouching for.

The five words that describe any run

A GitHub Actions run is a chain of five things. Learn these once and every CI file you ever read becomes legible:

An event (a push, a pull request) triggers a workflow (a YAML file in .github/workflows/), which runs one or more jobs, each on a fresh runner (a throwaway machine), each job a list of steps that run in order, top to bottom.¹

Full definitions live in the glossary — keep it open.

The one idea to keep A step passes when its command exits 0. The run is green only when every step exits 0. Green is a mechanical fact about exit codes — nothing more mystical than that.

Your run, decoded

Here is the verify job from your .github/workflows/ci.yml, exactly as it ran on PR #8 — triggered because you opened a pull request targeting main. Each row is one step; the ones marked ◆ are gates — a failure there turns the whole run red.

✓actions/checkout@v4Setup — copy your branch onto the runner.
✓actions/setup-node@v4Setup — install Node 22, restore the npm cache.
✓npm ciSetup — install exactly what package-lock pins.
◆npm run typecheckGate — tsc finds no type errors.
◆npm run lintGate — ESLint finds no violations.
◆npm run testGate — Vitest unit/component tests pass.
◆npm run buildGate — the Next.js production build compiles.
◆npm run build-storybookGate — Storybook builds.
◆npm run test:e2eGate — Playwright drives a real browser; axe checks WCAG. 3 passed.
✓upload-artifactAlways — save the Playwright report for later.

All green, in 1m48s. Six gates passed, so the tick is telling you: your change still type-checks, lints clean, passes every test, builds for production and for Storybook, and survives a real-browser accessibility scan.

So — is it safe to merge?

This is the heart of your mission. Green means precisely "every gate we declared passed" — and only that. Its trustworthiness equals the coverage of the gates. A green run cannot vouch for anything no step checks. Ask yourself:

Could this change break something none of these six gates would catch? If the answer is "yes, easily" (say, a visual regression, or a behaviour no test exercises), then green means "didn't trip the wires," not "provably correct." Trusting the tick is really trusting the gate list.

Green ≠ silent Your run also printed: "Node.js 20 is deprecated…". That is a warning — an annotation, not a failed step. The run stayed green because no command exited non-zero. Reading a run means noticing these: they are future red builds giving you notice.
