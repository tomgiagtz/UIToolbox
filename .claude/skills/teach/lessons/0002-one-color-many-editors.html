One color, many editors

How ColorPicker hands the same color to a hex box, three number fields, and a slider — without you threading a single prop between them.

In Lesson 1 you nailed questions 1 & 2 of the reading method: the state is one immutable Color object. This lesson is question 4 — how do the subcomponents share that state? — which is exactly the “Channel Fields” example you originally pointed at.

The puzzle in that example

Look closely at the docs example. The children carry no value and no onChange. Yet edit the hue slider and every number field updates. Where does the state come from? 

<ColorPicker value={color} onChange={setColor}>   {/* the value lives HERE, once */}
  <ColorArea  colorSpace="hsb" xChannel="saturation" yChannel="brightness" />
  <ColorSlider colorSpace="hsb" channel="hue" />
  {getColorChannels(space).map((channel) => (   {/* e.g. ["red","green","blue"] */}
    <ColorField key={channel} colorSpace={space} channel={channel} />
  ))}
</ColorPicker>

None of those children are wired to color. They don't need to be.

The answer: a compound component

ColorPicker is a compound component. It holds the one Color and publishes it through React Context; every child reads from and writes to that context. No props travel between siblings — the parent is the shared hub.

You can verify this yourself The context is a real, named export: ColorPickerStateContext (and the hook useColorPickerState) ship from react-aria-components. “Shares state via context” isn't a metaphor here — it's literally the API. A ColorField with a channel is just a consumer of that context that writes back one channel.

Contrast with what you'd do by hand: pass value/onChange to each field, and write merge logic so editing “red” rebuilds the whole color. The compound component does that plumbing internally. That's the trade you're evaluating this whole mission — less control, less boilerplate.

◆ <ColorPicker value onChange> Owns the one Color. Renders nothing itself — it's the state hub, put into context.
↳ <ColorField channel="red"> Reads context, shows red as a number, writes a new Color back on edit.
↳ <ColorSlider channel="hue"> Same context, different slice + different UI. Stays in sync for free.
↳ <ColorArea xChannel yChannel> Same context, two channels at once as a 2-D pad.

What channel and colorSpace actually do

Recall from Lesson 1: one Color can be read in any color space. That's what these two props exploit. A child says “I edit this slice of the shared color”:

  • colorSpace — which coordinate system to view the color in: "rgb", "hsl", or "hsb".
  • channel — which axis of that space this field edits: "red", "hue", "lightness"…

And getColorChannels(space) just tells you the axes a space has, so you can render one field per channel with a .map() instead of hard-coding three. It's a lookup, nothing more: 

getColorChannels("rgb")  // ["red", "green", "blue"]
getColorChannels("hsl")  // ["hue", "saturation", "lightness"]
Watch A ColorField with no channel edits the whole color as a hex string — that's the drop-in replacement for your current field. Add channel/colorSpace only when you want per-channel editing. You get to choose how much of this to adopt.

What this means for your swap

Your controls-ui.tsx replacement can stay tiny — one whole-color field inside a picker, with the Lesson 1 boundary seam: 

<ColorPicker
  value={parseColor(project.textColor)}
  onChange={(c) => dispatch({ type: "set-text-color", color: c.toString("hex") })}
>
  <ColorField><Label>Text color</Label><Input /></ColorField>
</ColorPicker>

The payoff of understanding the compound pattern: the day you want RGB number fields or a hue slider in the glyph editor, you drop them inside the same ColorPicker and they just work. You've bought optionality, not just a fancier input.

Reveal

The three fields switch from red / green / blue to hue / saturation / lightness — automatically, because the .map() is driven by getColorChannels(space). The underlying Color in the ColorPicker does not change; you're only changing which view of it the fields show. That's Lesson 1's “one color, read in any space” doing the work.
